# dsh-yu-memory · 鱼的记忆

两层记忆：**长期记忆**记住事实，**对话记忆**记住聊过什么——而且会忘。

装上就开始记，不用配置。

---

## 两层记忆各管什么

| 层 | 存什么 | 存哪 | 怎么写 |
|---|---|---|---|
| 长期记忆 | 事实、偏好、关系、承诺、长期状态、重要经历 | `~/.dsh/global-memory/store.json` | 模型调 `remember_global` / `forget_global` |
| 对话记忆 | 普通会话最近聊过的片段 | `~/.dsh/global-memory/chat.json` | **每轮自动记一条，不调模型** |

两层分开的原因：对话记忆会淡忘，长期记忆里稳定事实不衰减（只有状态和事件按重要度加权）。把「今天聊了什么」和「他是谁」混在一起，早晚会把一次偶然固化成性格。

---

## 安装

```powershell
dsh plugin --profile desktop add github:Speraymer/dsh-yu-memory
```

装完重启 DSH。**没有必填项**：默认就开着，下一轮对话开始记。

---

## 设置项

设置 →「鱼的记忆」。

| 字段 | 默认 | 说明 |
|---|---|---|
| 总开关 | 开 | 关掉 = 不记也不召回 |
| 每日新增上限 | `12` 条 | 长期记忆一天最多加这么多 |
| 每轮召回条数 | `6` 条 | 进上下文的长期记忆条数 |
| 每轮召回字数 | `800` 字 | 硬上限，不管条数 |
| 召回门槛 | 见设置页 | 低于这个分数不带 |
| 事件半衰期 | 见设置页 | 事件与状态按它衰减；稳定事实不衰减 |
| 对话记忆开关 | 开 | |
| 对话半衰期 | `3` 天 | 越久没被想起，越难召回 |
| 对话每轮带几条 | `6` 条 | |
| 保存后异步补检索词 | 关 | 打开后保存时多一次模型调用，补 related / factKey |
| 单会话排除 | — | 逐会话勾「不挂载记忆」 |

每个会话默认保留 80 条对话记忆，全局最多 800 条。

## 运行机制

**记一条对话记忆**：每轮结束取这一轮最后一段文字，截断、清洗、写入 `chat.json`。**不调用模型**，所以不会因为「有记性」多花钱。

**淡忘**：每条带一个激活度，按半衰期衰减；被再次召回时回血。衰减只降低召回概率，**不删内容**。

**召回打分**：`词重合 × 重要度 × 激活度`。分词用自带词典（`lib/词典.txt` + `词频.txt`），所以是**词面匹配**。

**提示提炼**：同一条被反复想起会提示「值得提炼进长期记忆」，但不会自动写进去——要不要长期保留由模型决定。

**写入安全**：临时文件 + 原子替换；改之前留 `.bak` 和每日快照；主文件坏了优先恢复备份，不静默返回空库。删除全是软删除，可恢复。

**不挂载的场景**：子代理、headless、自动化后台任务、归档对话、被你手动排除的会话——免得把后台噪声写进记忆库。

## 边界与已知限制

- **召回是词面的**：换个说法匹配不上。几百条够用，几千条后明显变差。
- **没有向量检索**：要多一次模型调用 + 索引维护，这个量级不划算。
- **每轮全量重写 `chat.json`**：原子写 = 临时文件 + 改名，条数越多单轮越慢。
- **没有永久清空**：设计上只有软删除；真想清就删 `~/.dsh/global-memory/`（长期记忆一起没了）。
- **3.0.0 起移除了「记忆图」**：那是第三层，靠手动连线决定这一轮看什么——必须有人操作才有用，不碰等于不存在，却占 9.6MB。

## 依赖与降级

- 不依赖任何其他插件，缺兄弟插件时静态降级。
- 设置页会顺带推荐另外七个插件，装不装都不影响它。
- 拿不到设置服务时退回读 `config.json`。
